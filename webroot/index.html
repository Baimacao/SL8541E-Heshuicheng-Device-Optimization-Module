[?] 怎么更新模块（有新版了）

首选：用根管理器卡片上的「更新」按钮。

> 根管理器会自己读仓库里的 update.json， 比对版本后在模块卡片上亮出更新按钮 —— 点它就行，管理器自己下载、自己安装

> 没看到按钮？下拉刷新模块列表，或重启一次管理器

> 装完要重启才生效

> 备选：命令行（管理器不带更新按钮时用）

su -c 'sh /data/adb/modules/SL8541E_Config_Fix/lib/install.sh install'

> 命令行方式点一次只检查，再点一次才真安装（防手滑）

> 如果提示"没有可用的安装 CLI"，包已下载到模块目录， 去管理器里手动安装即可：

/data/adb/modules/SL8541E_Config_Fix/update.zip

> 模块在 GitHub 上的地址见「关于」页

[?] 开机清理空文件夹——都删了什么

> 每次开机自动清一遍共享存储里的空目录， App 卸载后留下的空壳会被收走

> 只删空的：用的是 rmdir —— 它不是"先判断是不是空再删"，而是非空就删不掉，所以不存在误删

> 范围：Download / Documents / Pictures / Music / Movies / DCIM / Bluetooth / recordings 等常见目录，深度最多 3 层

> 不碰 Android/data（App 私有目录， 删了可能让 App 重建或异常），也不碰 /data /system /vendor

> 清理数量记在日志里：

grep 空文件夹 /data/adb/modules/SL8541E_Config_Fix/fix.log

> 想改范围就编辑 lib/common.sh 里的 CLEAN_DIRS

[?] 更新检查显示失败

> 这台表在国内，GitHub 时通时不通，属正常现象

> 检查走的是 /releases/latest 的跳转，不消耗 API 配额， 所以失败基本就是网络问题，不是被限速

> 挂了 hosts 加速的话，点一次「操作」刷新 DNS 守护再试

> 实在不行就手动下载安装包刷进去，功能完全一样

[?] 刷进去了，但没反应 / 找不到模块

> 先确认根管理器是 APatch / Magisk v20.4+ / KernelSU

> 不重启 = 没装。 模块的所有动作都挂在开机的两个钩子上

> 管理器 → 模块 → 确认本模块在列表里且已启用

> 安装时如果提示"这箱子是漏的"，说明压缩包不完整 → 重下

[?] 状态页显示一堆「未生效」

> 先重启一次。很多值只在开机那一刻写得进去，晚了就锁了

> 重启还这样，看日志（日志不骗人，鱼会骗你）：

cat /data/adb/modules/SL8541E_Config_Fix/fix.log

> 查冲突模块：Hc_memory（swappiness）、tcpboost（TCP 参数）、 dex2oat_4t（CPU set 写成 4,5,6,7 那个）—— 本模块已接管它们干的活，同时开就是互相打架

> 确认机型是 SL8541E / SC9832E + 和顺成（HSC）方案，别的方案属性名对不上

[?] 充电还是慢，根本没变快

> 模块把输入上限拉到 3A，但上限不等于实速，充电器才是天花板

> 5V 1A 充电头 → 实测约 890mA

> 5V 2A 充电头 → 能到 1500mA+

> 别插电脑 USB 口，那个永远锁 500mA

> 充电时 34~42°C 属正常；超过 45°C 建议改小，见下一条

[?] 表有点烫 / 想调小充电电流

> 编辑 lib/common.sh，把 CHG_TARGET=3000000 改成 1500000

> 单位是 µA：1500000 = 1.5A。写成 1500 会被拒绝（太小）

> 改完重刷模块或直接重启

> 温控阈值本模块一个字都没动，展锐的保护策略照旧生效

[?] GitHub 还是打不开

> 先看 hosts 挂上没有：

cat /system/etc/hosts | grep github

> 守护进程每 30 分钟探一次，刚开机可能要等

> 想立刻刷新：重启设备，或点一次「操作」按钮

> IP 池全失效了，就手动改 system/etc/hosts 换新 IP

[?] 动画还是卡 / 我想更省电

> 模块把 SurfaceFlinger 的背压和 vsync 同步恢复了，动画是完整的，但 A53 就这点渲染力

> 想更顺：设置 → 开发者选项 → 动画缩放，手动调到 0.5

> 想更省电：改回原厂省电取向，编辑 lib/prop.list，把这两行的值改成 1：

core|debug.sf.disable_backpressure|1

core|debug.sf.latch_unsignaled|1

[?] 音频有电流声 / 高码率音乐放不了

> 本模块一个字节都没碰 V4A（不动 audio_effects.conf、不动 soundfx）

> 硬件锁死 44100 Hz / 16bit，超出的音源播不了是硬件的锅，不是模块的

> 想听高采样率：只能外接 USB DAC

[?] 闹钟 / 定时器偶发不响

> 这个 bug 复现过一次，后来自己好了，本人至今没抓到凶手

> 唯一嫌疑是心跳上报属性，试着把它放回去：编辑 lib/prop.list， 删掉 core|persist.sys.heartbeat.enable|0 这一行，重启

> 顺手取证：

dumpsys alarm | grep deskclock

[?] 怎么彻底卸载 / 恢复原厂

> 根管理器 → 模块 → 删除本模块 → 重启

> 内置 uninstall.sh 会把模块写过的 persist 属性逐个清掉， 还会顺手停掉 DNS 守护（不然它变成孤儿进程继续跑）

> 卸载后虚标会回来，这是正常的——说明清干净了，原厂那套又接管了

> 清理报告：cat /sdcard/SL8541E_uninstall.log

[?] 能刷到别的表上吗（胆子肥嘟嘟的想法）

只适用 SL8541E / SC9832E + 和顺成方案。

> 别的方案刷进去，属性名对不上，表现是"装了个寂寞"

> 更坏的情况：充电节点路径不同，会写到一个不存在的节点，静默失败
